# 0.9.2 정차 조작 검증

P단 필수 조건을 제거했다. 차량 모드의 조작에는 최신 차속으로 확인한 완전 정차와 차량 OS의 화면 사용 허용이 모두 필요하다. OS의 제한을 해제하거나 앱을 distraction optimized로 선언하지 않는다.

`VehicleStopGate`는 차속 절댓값 0.01m/s 이하가 1초 동안 연속 수신되면 정차로 판별한다. 이는 영속도 센서 오차 허용 범위다. 0.01m/s를 넘는 이동은 전진·후진 모두 즉시 잠근다. 마지막 유효 표본이 0.5초를 넘거나, 유효하지 않은 값·미래 시각·권한 상실·연결 해제가 발생하면 다시 연속 정차 확인을 거쳐야 한다. 화면 상태 점검은 100ms마다 수행한다.

`MainActivity`는 상점·차고·확대/축소·수락·미리보기·결과 접근에 같은 조건을 적용한다. 제한 전환 시 열린 창을 닫고 대기 중인 매칭 제안을 취소한다. 진행 중인 대결의 종료 조건은 공통 구간 종료 또는 경로 이탈이며, 신호대기는 종료 조건이 아니다. 디버그 전용 단일 차량 신호 시험의 구간별 정산은 다기기 대결과 별개다.

## 실행한 검사

- 생산 코드 `VehicleStopGate`, `DuelEngine`과 `VehicleStopGateSmoke.java`를 JDK 17로 함께 컴파일·실행했다. 17개 단언을 통과했다. 무신호, 단일 영속도, 연속 정차, 신호 만료 경계, 복구 후 재확인, 저속 이동, 후진, 지연·중복·미래 시각, 비정상 값, 연결 초기화 및 신호대기 시 대결 유지가 포함된다.
- `:app:assembleDebug :app:lintDebug`를 실행했다. 로컬 SDK 경로의 콜론 이스케이프를 수정한 뒤 오류 없이 통과했다. 기존의 API·의존성·접근성 관련 lint 경고는 남아 있다.
- 공식 Pleos Connect 2.1.0 / API 34 / 2560×1440 AVD를 부팅하고 0.9.2 디버그 APK를 설치했다. 차량 서비스에서 CAR_SPEED 권한 필요 상태를 확인했다. D단 정차에서의 앱 조작, 주행 재개 시 창 닫힘과 결과 복귀는 이번 실행에서 검증을 완료하지 못했다. 이 설치 사실을 기능 검증으로 간주하지 않는다.
- 정상 권한 허용 화면을 이용한 공식 환경 재시험이 남아 있다. 실제 FCA 경고 수신도 미검증이다. 권한 필요 상태의 로그나 APK 설치만으로 차량 연동이 검증됐다고 판단하지 않는다.

## 재현 방법

일반 Android 디버그 모드는 기존 시연 흐름을 유지한다. 공식 Pleos에서는 앱의 차속 권한 허용 화면을 통해 권한을 허용한 뒤 Virtual Console의 차량 입력으로 시험한다. 콘솔은 브라우저 세션이 활성화돼야 차량 입력을 수신한다.

1. 영속도를 1초 이상 유지해 화면 접근을 확인한다.
2. D단 정차에서 OS 화면 제한의 실제 상태와 앱 화면을 함께 확인한다. OS가 제한하면 앱의 차속 판별만으로 화면을 열지 않는다.
3. 상점·미리보기를 연 상태로 출발해 창과 화면이 제한되는지 확인한다.
4. 다시 완전히 멈추면 연속 정차 확인 후 OS 허용 범위에서 화면이 복귀하는지 확인한다.
5. 차속 권한 거부·회수와 신호 단절 때 조작이 잠기는지 확인한다.

현재 공식 환경의 0.9.2 시연 녹화는 작성하지 않았다. 이전 일반 Android 영상이나 0.9.1의 60fps 프레임 출력 영상을 이번 공식 차량 연동 검증 영상으로 표시하지 않는다.
